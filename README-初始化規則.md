# 初始化文件索引

> 版本：v0.4
> 更新日期：2026-06-05

這份索引用來快速定位 `ai-toolkit` 專案內和「多專案初始化規則」有關的核心文件。

如果你要：
- 建立新專案
- 填寫新專案初始化資料
- 幫既有專案補初始化
- 調整 `startup` / `shutdown` 對接規則
- 修正 `CLAUDE.md` 欄位設計
- 執行初始化後驗證
- 排查既有專案補初始化問題
- 在 Windows / Linux / 不同設備間共用初始化規則
- 評估專案初始化是否適合做成 Codex skill

請先從這份索引開始。

---

## 先看哪一份

### 0. 新專案表單

- 檔案：`新專案初始化表單.md`
- 用途：開新專案前先填欄位，讓 Codex 依表單產生 `CLAUDE.md`、`.gitignore`、工作筆記與 GitHub 初始化流程

適合在這些情況先看：
- 要從零建立一個新專案
- 還不確定要提供哪些欄位
- 想用固定格式交給 Codex 初始化

---

### 0.1 新專案口令

- 檔案：`新專案口令規則.md`
- 用途：定義 `開始新專案` 及其同義句，避免每次輸入長路徑

適合在這些情況先看：
- 想確認有哪些短句可以觸發新專案初始化
- 要區分 `開始新專案` 和 `開工`

---

### 0.2 專案初始化 skill 化評估

- 檔案：`專案初始化skill化評估.md`
- 用途：判斷專案初始化是否應做成 Codex skill，以及 skill 與 `ai-toolkit` 文件規格的分工

結論摘要：
- 可以做成 skill，但 skill 只負責「觸發、導引、檢查、套用模板」
- 規格真相仍放在 `ai-toolkit` 文件內，不把完整模板硬寫死在 skill
- skill 應讀取本 repo 的表單、模板、欄位規格與驗證清單後執行

適合在這些情況先看：
- 要把「開始新專案」變成穩定觸發流程
- 要在 Windows / Linux 兩台 Codex 使用同一套初始化規格
- 要避免初始化流程只靠口頭記憶或單一對話

---

### 1. 總控說明

- 檔案：`CLAUDE.md`
- 用途：說明這個專案的定位、規則核心、以及初始化系統的總入口

適合在這些情況先看：
- 想理解這個專案到底管什麼
- 想知道初始化系統的核心原則
- 想確認目前規則是否已升級成多專案版

---

### 1.1 跨設備路徑

- 檔案：`跨設備路徑規則.md`
- 用途：定義 `AI_TOOLKIT_ROOT`、`PROJECTS_ROOT`、`OBSIDIAN_VAULT_ROOT`、`CODEX_HOME`，避免文件綁定某一台電腦的絕對路徑

適合在這些情況先看：
- 同一套文件要在 Windows 和 Linux 使用
- 雲端同步後，每台設備的專案位置不同
- 想判斷哪些路徑應該寫進共享文件，哪些應該留在本機設定

---

### 2. 套用模板

- 檔案：`專案初始化模板.md`
- 用途：把新專案或既有專案套上同一套初始化規則

適合在這些情況先看：
- 要建立新專案
- 要幫舊專案補 `CLAUDE.md`
- 要補 `.gitignore`
- 要建立 Obsidian 工作筆記
- 要依 SOP 檢查 git / GitHub / 路徑

---

### 3. 欄位規格

- 檔案：`CLAUDE欄位規格.md`
- 用途：定義每個專案的 `CLAUDE.md` 應該有哪些欄位，以及欄位的用途

適合在這些情況先看：
- 不確定 `CLAUDE.md` 該怎麼寫
- 要確認 `專案顯示名稱`、`專案代號`、`GitHub repo slug` 有沒有混用
- 要檢查工作筆記路徑是不是寫法一致

---

### 4. 驗證清單

- 檔案：`初始化驗證清單.md`
- 用途：初始化完成後逐項檢查，確認文件、GitHub、Obsidian、Codex 流程都對上

適合在這些情況先看：
- 新專案剛初始化完成
- 既有專案剛補完初始化
- 要確認 `startup` / `shutdown` 是否讀寫正確位置

---

### 5. 既有專案 SOP

- 檔案：`既有專案補初始化SOP.md`
- 用途：處理已有 git、已有 remote、搬移資料夾、repo slug 不一致等實務情境

適合在這些情況先看：
- 專案不是從零建立
- remote 狀態複雜
- 專案從其他位置搬到正式工作根目錄

---

### 6. 範例專案

- 資料夾：`examples/standard-project/`
- 用途：提供完整的 `CLAUDE.md`、`.gitignore`、`工作筆記.md` 成品範例

適合在這些情況先看：
- 想看模板套用後實際長什麼樣
- 要檢查欄位格式和工作筆記格式

## 核心原則摘要

- `CLAUDE.md` 是每個專案的單一真相來源
- 共享文件使用相對路徑與本機路徑變數，不綁死單一設備
- 跨 Windows / Linux / NAS 接續時，專案內固定狀態檔與 Obsidian 工作筆記並行
- `startup` / `shutdown` 必須先讀 `CLAUDE.md`
- Obsidian 工作筆記固定走 `專案庫/<專案代號>/工作筆記.md`
- `專案顯示名稱`、`專案代號`、`GitHub repo slug` 要分開
- 新專案初始化與既有專案補初始化要分流
